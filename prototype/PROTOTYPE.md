## 3. 两个入口与信息架构
### A. 会话上方“记忆”
- 右侧轻量抽屉；桌面保留对话，窄屏切为全宽面板。
- 已引用：第 1 轮的冻结演示快照，不保证模型真正采用其全部内容。
- 相关候选：已经保存、但尚未实际注入的候选；不是待保存提案。
- 卡片动作：查依据、为什么引用/推荐、下轮不用、固定下轮候选。
- 底部：本会话暂不调用、记住一条、管理全部记忆。
- 下轮候选不保证实际注入；正式装配必须重新校验权限、有效期和预算。
- 保留聊天草稿；跨工作台返回时保留抽屉及演示选择。

### B. 设置 → 插件 → agentOS context
- 原有配置卡：自动记忆、写入前提炼、提炼模型；新增关联理解/召回分离的目标配置。
- 修改先保留草稿，明确“保存设置”；跳转前提示放弃或继续。
- “打开记忆工作台”进入共享管理视图，不建立第二套记忆数据。
- 工作台只有四个一级 Tab：记忆、图谱、待确认、设置。
- 记忆：列表、对象档案、来源资料；搜索、范围/状态筛选、详情。
- 图谱：一/两层展开、解释路径、节点与边详情、关系文本列表、演示时间轴。
- 待确认：备份策略冲突、同类型需求别名候选；预览、填写理由、确认与撤销。
- 设置：基础与隐私；高级类型/关系校验和规则发布门禁示意。

## 4. 核心可点流程
1. 设置 → 工作台 → 记忆列表 → 查看证据 → 关系/版本。
2. 会话 → 记忆抽屉 → 下轮不用 → 工作台 → 返回会话；已引用快照不变。
3. 会话输入“记住：内容” → 预览内容和范围 → 保存；新记录在工作台同一数据源可见。
4. 记住一条 → 空内容提交 → 错误提示；取消不留半条记录。
5. 修订 → 填写理由 → 保存；冻结的第 1 轮引用内容保持原样。
6. 停止召回 → 影响说明 → 理由 → 确认；不物理删除原文或历史对话。
7. 图谱 → 两层 → 选中关系 → 展开对应依据；不是所有关系共用一个证据片段。
8. 输入“为什么需要二次确认” → 高亮固定演示路径；其他问题明确未接入模型。
9. 时间滑块 → 旧方案/评审/约束/当前；仅四个固定演示点，不是完整时态数据库。
10. 待确认 → 并列来源 → 采用正式纪要或区分环境 → 理由 → 保存；可撤销。
11. 别名候选 → 合并预览 → 理由 → 确认；需求与接口仍是不同实体。
12. 类型与关系 → 主语选择 Person → 校验失败；切换 Requirement → 校验通过。
13. 离线/无权限/不可追踪/来源不可访问 → 不伪造成功 → 恢复演示状态。

## 5. 状态矩阵
| 状态 | 原型入口 | 展示 | 恢复与限制 |
| --- | --- | --- | --- |
| ready | 默认 | 真实可点的演示内容 | 本地模拟写入 |
| loading | 顶部演示状态 | 骨架与加载说明 | 模拟完成加载 |
| empty | 顶部演示状态 | 首次使用说明 | 载入示例资料；不是删除现有数据 |
| dirty | 修改设置 | 明确未保存与保存/取消 | 导航需确认 |
| saving | 记忆/审核提交 | 按钮显示保存中且禁用 | 模拟约 280ms 本地提交 |
| success | 保存/排除/审核完成 | 可见结果与提示 | 适用操作提供撤销 |
| error | 顶部读取失败 | 原因、未保存说明、重试 | 重试恢复 |
| disabled | 顶部插件停用 | 不可用原因 | 模拟启用，非真实配置 |
| offline | 顶部离线只读 | 缓存提示 | 写操作禁用 |
| denied | 顶部无权限 | 隐藏主内容与证据 | 不把无权限解释为无数据 |
| stale | 顶部并发冲突 | 提交拒绝、草稿仍在弹窗 | 不做最后写入覆盖；取消后可回正常态 |
| traceUnavailable | 顶部引用不可追踪 | 明确没有真实引用记录 | 不使用相关列表冒充引用 |
| sourceUnavailable | 顶部来源不可访问 | 不展示不可访问原文 | 不生成替代原文 |
| truncated | 顶部图谱截断 | 显示局部结果限制 | 缩小范围并重试 |

## 6. 三条状态轴的展示
- 保存/记录状态：是否进入共享演示记忆、是否停止召回。
- 依据状态：来源已核对、存在冲突、推断待确认；来源核对不等于客观真或验收通过。
- 使用状态：第 1 轮已引用、相关候选、后续排除/固定；不更改历史快照。
- 原型为交互演示，部分记录状态用 display status 简化存储；正式三轴数据模型以完整方案为准。
- 新用户修订以用户修订来源标识，不把新文本冒充原始需求文档。

## 7. 无障碍与响应式
- 所有业务动作有文字或可访问名称；状态不仅靠颜色表达。
- 业务表单支持键盘，模态 dialog 提供原生焦点约束；Esc 关闭。
- 会话抽屉桌面为非模态，不锁住聊天；关闭焦点回“记忆”触发点。
- 依据面板独立焦点循环，图节点/边支持 Tab + Enter/Space。
- 窄屏保留操作入口，表格转卡片，图谱可局部横滚并提供关系列表，禁止整页横向溢出。
- 遵守 prefers-reduced-motion；不使用持续动画。
- 实际检查 375×812、768×1024、1440×900；720×450用于200%缩放的等效CSS视口检查。
- 深/浅色按已读取的默认 token 模拟；真正的 DSH 系统主题、用户字号偏好与宿主原生组件同屏验收仍需正式集成。

## 8. 数据、安全与限制
- 全部业务数据为虚构 Atlas/DEMO-042，不含真实员工、事项内容、生产路径或密钥。
- 数据仅存在当前页面内存；无 localStorage、cookie、数据库、模型调用、网络同步。
- 页面设置 Content-Security-Policy，connect-src 为 none；使用文本转义防止示例输入成为 HTML。
- 冲突、保存、停止召回、撤销、类型校验均为有状态模拟，不是后端事务证明。
- 任意本体编辑、OWL/RDF推理、全量双时态、ACL、模型提取、迁移、导入导出、永久删除均未实现。
- 身份合并、永久删除与规则发布的正式流程必须另审影响、权限和补偿；原型不承诺无条件可撤销。
- 同屏右抽屉依赖正式 overlay/trigger slot 合同。第一可运行检查点先使用已验证的原生 conversation.view“记忆”Tab，并保留常驻 composer；不能把原型效果当成现有 slot 已支持右抽屉。
